# ML-KEM 核心 206 MHz 修改与验证记录

日期：2026-10-03。修改基线：`49a144c`。本次只优化 ML-KEM 核心；UART bridge、RX、TX 的 RTL 与基线逐字节相同，UART 时钟保留 100 MHz。

**当前交付：第二轮代码已通过 Vivado 2024.1 完整实现，核心 206 MHz、UART 100 MHz。WNS +0.093 ns、WHS +0.036 ns、WPWS +1.177 ns；建立、保持、脉宽失败端点全部为 0。** 用户随后授权使用现有 `vivado-container`，本次在该容器中串行完成两轮验证，没有修改 Docker image，没有安装或下载工具。当前源码与第二轮实现输入的 28 个 RTL/约束文件 SHA-256 一致。

最终报告见 `reports/core206_debug2/`，其中 `implemented.dcp` 是已通过的布局布线检查点，`source_hashes.json` 标识实现输入。详细交付和比较见 [CORE_206MHZ_ROUND2.md](CORE_206MHZ_ROUND2.md)。

## 时序问题的定位依据

截图中的 WNS −4.993 ns、5094 个失败端点与已有 `reports/f206_0` 一致。仓库后续的历史报告 `reports/f206_3` 是 206.25 MHz、WNS +0.012 ns、WHS +0.034 ns，余量非常小；其核心资源为 LUT 7657、FF 4732、RAMB36 3、DSP 2。这些都是旧版本的实现结果，不能用于证明本次修改后的设计。

历史关键路径位于 sponge 的 Keccak 状态反馈，组合完成一整轮，且布线延迟占比较高。因此本次拆分轮函数，并减少部分控制和数据通路的选择逻辑。

## 核心修改

### 1. Keccak 轮函数分为固定两拍

`keccak_sponge.sv` 在第一拍计算并保存 Theta 的五列修正量 D[x]，第二拍完成状态异或、Rho、Pi、Chi、Iota 并提交状态。计数器只在第二拍递增。每次置换由 24 拍变成 48 拍；SHAKE128 一个完整吸收块由 21 拍输入、1 拍提交及 48 拍置换构成，共 70 拍。

这使完整轮的组合反馈被寄存器切开。保存 D[x] 复用了置换期间不参与外部握手的 `x_data`、`squeeze_data`、`nx1`、`nx2` 四个 64 位寄存器，只新增 64 位 `theta_hi` 数据寄存器及阶段控制，避免另建完整 320 位寄存器组。复用期间吸收 ready 和挤出 valid 不会宣告有效数据；每次重新开始置换及复位均初始化阶段控制。

状态按 lane 设置明确的写使能。容量部分不参与吸收更新；rate 部分仅在对应输入或 padding 操作发生时更新。挤出 lane 选择改为并行的 one-hot 与或逻辑，减少优先选择链。以上都是 RTL 结构优化，是否转化为更好的布局布线结果仍取决于综合映射。

`keccak_round.sv` 默认仍可组合计算完整一轮；`keccak_f1600.sv` 的独立接口保留 24 拍置换行为，避免改变其他使用者的延迟约定。

### 2. 控制器读 FIFO 改为分布式 RAM

新增 `mlkem_word_fifo.sv`，替代六个 32 位字的移位寄存器队列。偶数、奇数地址分别放入两个 4×32 位的分布式 RAM bank，每个 bank 提供一个异步读口，因此可同时查看连续两个队头字。指针负责出队，不再整体移位。

物理存储为 8 个字，控制器可用容量仍是 6 个字；原有未返回 BRAM 读取的预约规则保持不变。支持每拍入队 1 个字、出队 0/1/2 个字及同时入队出队。复位只清指针和计数，队列未满/非空规则由控制器保证。RAM 不复位有利于 LUTRAM 推断，逻辑上失效的存储内容不会作为有效数据消费。

物理 RAM 为 256 位，替代原来的 192 位移位存储。Vivado 路径报告已确认使用 RAMD32；扁平化与跨层优化后，存储 LUT 会归入父层级，不应把 FIFO 子层级显示的 LUTRAM=0 误判为推断失败。最终整体核心资源见第二轮报告。

### 3. 压缩通路收窄

`mlkem_pack.sv` 保留乘以 161271 的常数乘法及原有流水延迟，将后面的 41 位可变移位与加法，替换为 29 位加法、预解码偏置和固定切片。对有效系数 x、压缩位宽 d，使用恒等式：

```text
C = 1664 × 161271 = 268354944
floor((x × 161271 × 2^d + C) / 2^29)
= floor((x × 161271 + floor(C / 2^d)) / 2^(29-d))
```

结果按 2^d 取模，所以只需要保留乘积/加法结果的低 29 位。d=1…11 分别取固定切片；d=12 仍走不压缩的原始系数通路。加入 27 位的偏置寄存器是这一优化的面积权衡，不能将位宽差直接当作最终 FF 节省量。

### 4. 地址计算共享加法器

`mlkem_ctrl.sv` 的有效地址先选基址，再做一次 14 位加法，代替分别计算两个候选地址后选择。三个操作数地址对应的 RTL 加法表达式由六个减少为三个。微码、RAM 布局、NTT/INTT/BMUL 算法和密文比较流程不变。

### 5. 核心时钟精确配置为 206 MHz

Arty A7 顶层 MMCM：输入 100 MHz，DIVCLK_DIVIDE=5，CLKFBOUT_MULT_F=51.5，输出除以 5；VCO 为 1030 MHz，核心输出为 206.00 MHz。UART 保持原来的 100 MHz。没有增加 false-path 或 multicycle 例外来掩盖核心时序路径。

### 6. 解包器与密文比较流水化，预取选择预解码

解包器把宽窗口的可变移位分成两级：先按字节选出 19 位窗口并寄存，再做 0…7 位的细移位和字段掩码。有效信号同步增加一拍，吞吐率仍是每拍最多两个字段；复位和新任务启动都会清空新增有效位。控制器把 32 位密文比较拆成四个 8 位比较的寄存结果，再归并为 sticky flag；C_NEXT / C_FETCH 的已有间隔确保最后一次比较在 CSEL 之前生效。

第二轮将 sponge 的二进制预取索引改为寄存的 one-hot 选择。每次完整取走 lane 时左移一次，半 lane 消费时保持；新置换输出装载时回到 lane 3，超出 rate 后自然移为零。该改动不额外增加执行周期。

## 无功耗侧信道防护的实验实现

代码审查未发现对秘密值做掩码分份（masking）、运算乱序（shuffling）、盲化（blinding）或随机等待等功耗侧信道防护。Keccak 流水化使用固定调度，复用寄存器和 FIFO 改写均为实现优化。算法要求的随机种子、CBD 与 SampleNTT 采样保留；总线字节掩码和位运算 mask 不属于秘密共享防护。

密文比较、CSEL、隐式拒绝（implicit rejection）及输入有效性检查属于 ML-KEM 功能，全部保留。这里的“无保护”特指未加入功耗侧信道对策，不代表删掉算法必要校验。RTL 变化会改变切换活动和时序位置，后续 CPA 应针对本次比特流重新采集和对齐，不能沿用旧版本的采样窗口，也不能从功能仿真推断 CPA 成功率。

## 工程接入与复现

现有 `scripts/vivado_build.tcl` 使用 `hdl/core/*.sv` 自动收集源文件，已覆盖新增模块。此次通过 `scripts/vivado_reports.tcl` 运行非工程模式的综合、布局布线及报告。若使用原先手动添加源文件的 GUI 工程，需将 `hdl/core/mlkem_word_fifo.sv` 加入源文件集，否则会出现模块未找到。

在项目根目录运行以下命令可重复本次离线 RTL 检查，不调用 Vivado、不安装工具：

```bash
bash scripts/check_core206.sh
```

`reports/core206_debug2/source_hashes.json` 标识本次交付的 RTL/约束文件；旧 `reports/f206_*` 保留为历史结果。UART 测试脚本仅更新核心耗时换算的频率元数据，没有调整串口协议或 UART RTL。
