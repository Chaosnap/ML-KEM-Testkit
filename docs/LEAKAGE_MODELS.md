# 泄漏模型速查：寄存器里之前是什么、之后是什么、泄漏怎么算

对应代码：`cpa_toolkit/models/`（每个文件一个模型），共用部分在 `models/base.py`。RTL 位置和流水线拍见 [ATTACK_MODEL.md](ATTACK_MODEL.md) 第 4.2 节。

模型分两类：

| | **寄存器模型**（`hw_*` / `hd_*`） | **流水线模型**（`pipe_*`） |
| --- | --- | --- |
| 假设 | 指定一个寄存器，一条 trace 一个假设值 | 跟着 RTL 的发射时序走，**每个时钟周期一个假设值** |
| 前态 R_prev | 由 `--rprev` 选（zero / prev-word / acc） | 不需要选：前态就是上一拍那个乘法器真正在算的东西 |
| 和 trace 怎么对 | 和 BMUL 窗口里**每个采样点**做相关，取最大 | 每个假设和**它自己那一拍**的特征做相关，再求和 |
| 需要什么 | 采样率可选 | 必须有采样率（要把 trace 折成每周期一个值），还要搜一个整数周期偏移 |
| 代码 | `models/base.py: LeakageModel` | `models/base.py: PipelineModel` + `mlkem_pipeline.py` + `aligned_cpa.py` |

第 1–5 节讲寄存器模型，第 7 节讲流水线模型和它们为什么更贴近这颗核心。

---

## 1. 统一结构

每个模型都在算

```
leak(trace i, 猜测 g) = f( R_prev , X )
```

- **X（之后的值）**：这一拍写进寄存器的新内容，由猜测 g 决定；
- **R_prev（之前的值）**：写入之前寄存器里的内容；
- **f**：HD 模型是 `popcount(R_prev ⊕ X)`，HW 模型是 `popcount(X)`。

CMOS 寄存器的动态功耗正比于翻转的位数，所以用 R_prev ⊕ X。HW 相当于假设 R_prev = 0。

CPA 对每个候选 g（0…3328）算出所有 trace 的 leak，与实测功耗逐采样点做 Pearson 相关，取 max |ρ| 排名。

---

## 2. 五个模型一览

| 模型（文件） | 寄存器（RTL） | 位宽 | X：之后的值 | R_prev：之前的值（可选） | 泄漏 |
| ------------ | ------------- | ---- | ----------- | ------------------------ | ---- |
| `hw_scalar` | `p00` / `p11`（T+11） | 12 | `a_j · g mod q` | 无（视为 0） | `HW(X)` |
| `hd_scalar` | `p00` / `p11`（T+11） | 12 | `a_j · g mod q` | `prev-word`：上一个字（w−1）的同一乘积；`zero`：0 | `HD(R_prev, X)` |
| `hd_basemul_c0` | `h0`（T+17） | 12 | `c0`（偶输出系数，含 C_old） | `prev-word`：上一个字的 c0；`zero`；`acc`：C_old 的偶系数 | `HD(R_prev, X)` |
| `hd_basemul_c1` | `h1d[4]`（T+18） | 12 | `c1`（奇输出系数，含 C_old） | `prev-word`：上一个字的 c1；`zero`；`acc`：C_old 的奇系数 | `HD(R_prev, X)` |
| `hd_basemul_word`（默认） | `wb` / `wbd` / `rb_din`（T+18…21） | 24 | `{c1, c0}` = `c0 \| (c1 << 12)` | `prev-word`：上一个字的 `{c1, c0}`；`zero`；`acc`：`{C_old[2w+1], C_old[2w]}` | `HD(R_prev, X)` |

第 1 个多项式（poly = 0）没有 C_old，`acc` 取 0；第 1 个字（w = 0）没有上一个字，`prev-word` 取 0。

---

## 3. X 是怎么算出来的

对第 w 对系数（w = 0…127），被猜的系数 `j`，`e = j & 1`：

```
a0 = û[poly][2w]        a1 = û[poly][2w+1]        (公开)
b0 = ŝ[poly][2w]        b1 = ŝ[poly][2w+1]        (其中第 e 个被替换成猜测 g)

p_self = a_e · g mod q                              ← hw_scalar / hd_scalar 的 X
c0 = (a0·b0 + γ_w · (a1·b1 mod q)) mod q            γ_w = ζ^(2·BitRev7(w)+1)
c1 = (a0·b1 + a1·b0) mod q
poly ≥ 1:  c0 += C_old[2w],  c1 += C_old[2w+1]   (mod q)
X_word = c0 | (c1 << 12)
```

---

## 4. 需要用到的中间值

| 中间值 | 含义 | 来源 | 公开？ | 用在哪 |
| ------ | ---- | ---- | ------ | ------ |
| `û` (3×256) | `NTT(Decompress₁₀(c1))`，密文第一部分 | 从每条 trace 的密文 `ct` 算出 | **公开** | 所有模型的 a0、a1 |
| `ŝ` 的搭档系数 | 同一对里没被猜的那个（b0 或 b1） | 打分模式：真密钥 `dk` 解码；盲攻击：已恢复的猜测（没恢复的为 0） | 密钥相关 | c0、c1、word |
| `γ_w` | BaseMul 的常数 `ζ^(2·BitRev7(w)+1)` | FIPS 203 常数表 | 公开 | c0 |
| `C_old` (poly×256) | 前面多项式的累加和 `Σ û_i ∘ ŝ_i`（i < poly） | 由 û 和 ŝ（真密钥或已恢复）算出 | 密钥相关 | c0、c1、word 的 X；R_prev = `acc` |
| 上一个字的 X（w−1） | 同一遍 BMUL 的前一个字，用同样公式算 | 同上，w−1 | 密钥相关 | R_prev = `prev-word` |
| 窗口采样点 | BMUL 的 ~281 个周期（±40）对应的采样 | `config.BMUL_WINDOWS` + 采样率 | — | 与 leak 做相关 |

**对猜测 g 来说：** 只有 X 随 g 变化。`prev-word` 的上一个字属于另一对系数，不含这个猜测，所以对候选值是常数项，只改变 HD 的基线。`acc` 的 C_old 也不含当前多项式的猜测。

**盲攻击与打分模式：** 搭档系数、C_old、上一个字都依赖 ŝ。打分模式用真密钥（只用来评估，不是真实攻击）；盲攻击用前面已恢复的猜测，一对里先猜的那个系数的搭档只能按 0。

## 5. 示例（默认模型，poly = 1，猜 ŝ[1][5]，w = 2，e = 1）

```
b1 = g（猜测）            b0 = ŝ[1][4]（搭档）
X       = { c1, c0 } ，c0 = a0·b0 + γ_2·a1·g + C_old[4] ，c1 = a0·g + a1·b0 + C_old[5]   (均 mod q)
R_prev  = 上一个字 w=1 的 { c1, c0 }（用 ŝ[1][2]、ŝ[1][3] 和 C_old[2]、C_old[3] 算）
leak    = popcount( R_prev ⊕ X )    （24 位）
```

## 6. 寄存器模型的已知局限

- 这些模型是项目根据 RTL 推出的设计假设，没有 ML-KEM 专用的文献出处；通用的 CPA / 汉明距离思路见 Brier 等，CHES 2004。
- 6+5 级延迟副本（`p00d`、`h1d`）没有建模，只建了"当前字"和"上一个字"。
- **`prev-word` 这个前态假设和硬件对不上**（下一节）：这是第 7 节那组模型存在的原因。
- 真实硬件上是否这样泄漏尚未用示波器验证；用 TVLA 和 GUI 的 *Compare models* 对比。

## 7. 流水线模型（`pipe_*`）：按 RTL 的发射时序建模

### 7.1 `prev-word` 错在哪

`hd_*` 系列假设：第 w 个字进来时，寄存器里留着的是第 w−1 个字**同一个乘积**。看一眼
`mlkem_poly_alu.sv` 第 225-247 行的操作数多路选择就知道不是这样——两个乘法器**每一拍都接一个新运算**，而且两种运算交替：

```
mul0:  ... A0(w−1) , K(w−1) , A0(w) , K(w) , A0(w+1) ...     A0 = s0·u0,  K = (s0+s1)·(u0+u1)
mul1:  ... A1(w−1) , G(w−4) , A1(w) , G(w−3) , A1(w+1) ...   A1 = s1·u1,  G = (a1·b1)·γ
```

所以 `p00` 这一拍到下一拍的翻转，是 `A0(w)` 和 **`K(w)`** 之间的汉明距离，不是 `A0(w−1)` 和 `A0(w)` 之间的。
把 `hd_*` 的假设和仿真里真实的翻转数去比，相关系数只有 **0.01 左右**；按真实时序建模是 **0.3 左右**
（`scripts/sim/model_vs_rtl.py`）。

### 7.2 软件孪生：`mlkem_pipeline.py`

把两个 `mlkem_modmul` 的每一级流水线寄存器（`a0 b0 p1 p2 sa4 sb4 pl4 qh5 pl5 qq6 pl6 r`）和
复制它们输出的那些寄存器（`p00 p11 p11d p00d[0..5] mr mr2`）**逐位**复刻一遍，按上面的发射顺序算
每一拍的汉明距离。正确性不是靠读代码保证的：

```bash
python scripts/sim/pipeline_check.py          # 和 Verilator 仿真逐周期比对
```

它把 Decaps 跑一遍、把 RTL 每个寄存器每一拍的翻转数导出来（`tb_core.sv` 的 `+hd=`），和孪生算的值比。
全部 35 个寄存器、三次解密 BMUL 的每一拍都**完全一致**；故意把某个寄存器的延迟改错一拍，或者换成
"上一个字同一运算"的假设，比对立刻报错。

### 7.3 四个模型 = 四组触发器

探头放在芯片不同位置，耦合到的触发器不一样，所以按物理分组各做一个模型：

| 模型 | 覆盖的触发器 | 位宽合计 | 什么时候用 |
| ---- | ------------ | -------- | ---------- |
| `pipe_all` | 全部（下面三组之和） | 602 | 默认，先用它 |
| `pipe_dsp` | `a0 b0 p1 p2`（DSP48 的 A/B、M、P 寄存器） | 144 | 探头在 DSP 列上方 |
| `pipe_barrett` | `sa4 sb4 pl4 qh5 pl5 qq6 pl6`（约减的移位加，LUT 里） | 278 | 单组里最宽的一块 |
| `pipe_output` | `r` 和复制它的那些寄存器 | 180 | 探头看到的是乘积传递链 |

### 7.4 为什么"每拍一个假设"更强

同一个系数的数据会在流水线里停留约 15–17 拍（当前字的运算 + 延迟副本）。寄存器模型只能在窗口里
挑一个最好的采样点，而这里每一拍都是一条独立证据：真密钥在每一拍上都是正相关，错误猜测是噪声，
求和之后信号按 K 增长、噪声按 √K 增长，等效相关系数约提升 **√K ≈ 4 倍**。

trace 要先折成"每个核心周期一个值"（`cycle_features.py`）：先从跨 trace 的方差里估出时钟相位
（不需要密钥，也不需要模型），再把每个周期的采样点用 `pca`（从 trace 里学出探头的单周期波形，相当于
匹配滤波）、`energy` 或 `abs` 压成一个数。这一步让"探头到底是正是负、响铃几个采样点"不再需要猜——
**对只有一个 EM 探头的台子特别重要**。

最后还要搜一个整数周期偏移（trigger 到采样点 0 之间的线缆/放大器延迟，只有台子自己知道）：
`--offsets -6:6`，结果里会报告大多数系数落在哪个偏移上。**偏移集中在一个值 = 对齐是真的**；
知道之后填回去（`--offsets 2`）会更快也更干净。

### 7.5 怎么跑

```bash
python cpa_attack.py FILE.hdf5 --model pipe_all                  # 盲攻击
python cpa_attack.py FILE.hdf5 --model pipe_all --coeffs 8        # 先看 24 个系数
python cpa_attack.py FILE.hdf5 --model pipe_dsp --features energy --offsets 2
```

GUI 的 Analysis 页选 `pipe_*` 时会多出 *Trace feature* 和 *Cycle offsets to search* 两个设置；
报告头部会写明用了哪种特征、一个系数占几拍、周期偏移集中在哪。

### 7.6 局限

- **等权重假设**：每个触发器算一样重。真实探头对不同区域灵敏度不同，所以才分出 `pipe_dsp` /
  `pipe_barrett` / `pipe_output` 三个子模型，实测时应当都跑一遍比较（*Compare models*）。
- 只覆盖了两个乘法器及其输出复制链，**没有**覆盖 Karatsuba 的两次减法（`s1`、`h1`）、累加器读回
  （`cd[0..13]`，poly 1/2 才有）和写回（`wb`、`wbd`、`rb_din`）——这些寄存器携带的是同一批数据，
  只是晚几拍。
- 盲攻击时，一对系数里**先猜的那个**（偶数下标）拿不到搭档的值，也拿不到后面字的值，所以只用
  那些不依赖它们的转移（`mlkem_pipeline.terms_for(..., causal=True)`）——假设数变少，强度相应下降。
- 这些都是**无噪声的汉明距离上界**，不是对实测相关系数的预测。
